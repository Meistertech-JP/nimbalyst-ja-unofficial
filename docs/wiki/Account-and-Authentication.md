# アカウント認証

## v0.82.3-ja.1

通常製品での認証・NSIS導入・更新・削除操作はこの版では再実施していません。今回の製品変更では認証およびインストーラーの入力・設定を変更していませんが、これは実操作の確認に代わるものではありません。過去製品の認証結果はそれぞれの版に限定した履歴です。Google認証、特殊復旧、サーバー側セッション失効、別ユーザーのNTFS実効アクセスも未検証です。以下は実装上の手順・保存方針を説明します。

## v0.82.1-ja.1

メール認証は通常のWindows製品ビルドで確認しています。同じPCのブラウザーからlocalhost callbackを受理し、暗号化保存、正常終了後の認証復元、通常サインアウト、再起動後の未認証状態保持を確認しました。nonce不一致と再受理拒否は契約テストで検査しています。実アカウントのcallbackを改変・再送する試験は行っていません。Google認証、特殊な復旧経路、サービス側のセッション失効、他アカウントからのNTFS実効アクセスは未検証です。

Nimbalystアカウントは正規のNimbalystサービスを利用します。このフォークが別の認証サーバーやアカウントを提供するわけではありません。Nimbalystへのログインと、Claude・Codex・Grokなど個々のエージェントの認証は別です。

## メール認証

1. アプリのアカウント画面からメール認証を開始します。
2. メールを受信したら、アプリを起動している同じWindows PCでリンクを開きます。
3. ブラウザーで認証した後、現在のインスタンスのlocalhost callbackへ戻ります。
4. アプリ側でアカウント表示が更新されたことを確認します。

コールバックは`http://127.0.0.1:<port>/auth/callback`です。インスタンスごとのnonceを持ち、受理は単回使用として扱います。URL・nonce・認証コード・Magic Linkの実値を共有しないでください。

`127.0.0.1`はブラウザーを実行している端末自身を指します。スマートフォンでメールのリンクを開くとスマートフォン自身へ接続するため、Windows上のアプリへ認証結果を返せません。使用済み・期限切れならPCのアプリから新しいメールを要求します。URLの書換えや外部向けのポート開放は行いません。

## 保存・復元・ログアウト

Windowsでは認証情報を暗号化して保存し、保存成功後にサインイン状態を反映する実装です。暗号化保存に失敗した場合、平文保存へ切り替えずエラーを通知します。ローカル認証情報とログアウト状態の競合を避けるため、古い非同期更新応答で状態を戻さない処理があります。

v0.82.1-ja.1の検証では通常製品ビルドの実認証を確認しました。v0.82.3-ja.1では認証を再実行していません。過去の版の検証範囲は各版のリリースノートに記録しています。

ログアウトによるローカル情報の削除は、サービス側セッションの失効、トークン更新の全経路、アカウント削除とは異なります。サービス側の失効まで保証していません。Google認証とStytchの一部の復旧経路は未検証です。

認証ファイルやSQLite関連ファイルの権限観測は、他のユーザー・グループを含むNTFS実効アクセスの検証ではありません。検証範囲は[リリースノート](https://github.com/Meistertech-JP/nimbalyst-ja-unofficial/releases/tag/v0.82.1-ja.1)と[テストと品質検証](Testing-and-Verification)を参照してください。

## 公式版との関係

Windows版は`nimbalyst://`の既定ハンドラーを取得せず、認証にlocalhostを使用します。認証以外の同プロトコルのリンクは既存の登録先アプリで開く場合があります。アプリ識別子とプロファイルは分離していますが、公式版との同時利用はサポートしません。

問題がある場合は[トラブルシューティング](Troubleshooting)へ進んでください。診断資料にプロファイル全体、Cookie、トークン、メール内リンクを添付しないでください。
