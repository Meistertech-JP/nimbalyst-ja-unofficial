# 非公式日本語版のソースリリース

公開名は「Nimbalyst 日本語版（非公式）」／「Nimbalyst — Unofficial Japanese Edition」、対象バージョンは `v0.81.7-ja.1` です。ベースは公式デスクトップ版v0.81.7のコミット `79b8c560c491061c39ea70d01097139055b62ae8` です。ソース限定プレビューには実行バイナリ、更新マニフェスト、認証データを添付しません。

## 履歴の統合方針

公開済みの `origin/main` と `v0.71.2-ja.1` はコミット `6365b2cd46f08e9255e08f0ef96d6c31174e6bd9` を指します。現在の開発HEADの親は `b63505a9e`、公開mainとの共通祖先は公式v0.71.2の `59ab7eaf8c995840a37766c65a09307506b87a2b` です。公開main側だけに1コミット、開発HEAD側だけに1,224コミットあります。

推奨する次工程は、検証済みのv0.81.7ソースを現在の開発履歴上で明示的なファイル一覧からコミットし、別の統合用worktreeで公開mainを第1親、その検証済みコミットを第2親とするマージを作成することです。旧版の翻訳変更を機械的に混ぜ直さず、マージ結果のツリーを検証済みv0.81.7ツリーと完全一致させて照合します。この方法で旧mainは新mainの祖先として残り、通常のfast-forward pushが可能になります。旧タグとReleaseは変更しません。

統合用マージでは旧履歴の保持とソースツリーの選択を明示し、通常マージの競合解消に任せません。元の作業ツリーでreset、stash、clean、破棄を伴うcheckoutを使いません。新タグは検証済みマージコミットに作成します。force pushは使用しません。

## 公開前の検証

英日リソースのキー、補間変数、空欄、参照先を `node scripts/audit-ja-source.mjs` で確認します。動的翻訳キーと表示用英語の候補は別途分類します。型チェック、関連テスト、Runtime、Collab、Electron、Workerのビルド結果を記録します。第三者ライセンスは依存ツリーから再生成し、元のMITライセンスと著作権表示を保持します。

未追跡ファイルは個別に採否を決め、実装・リソース・回帰テスト・公開文書・再現可能な型定義のみを候補にします。`node_modules`、実ユーザー設定、秘密情報、認証キャッシュ、ログ、失敗した実行ファイル、ビルド中間生成物、ローカル監査出力は含めません。`.env.example` と明示的なデモ・テストfixtureは内容を確認して区別します。

## 承認後の公開手順

1. ローカル保全の検証結果、公開候補ファイル一覧、秘密情報候補の分類、全検証結果を確認します。
2. 公開候補だけを明示的なパス指定でstageし、差分を再確認して開発履歴上のコミットを作成します。
3. 別worktreeで上記の履歴統合を行い、結果のツリーIDが検証済みソースと一致し、旧mainが祖先として残ることを確認します。
4. remote URLが `https://github.com/Meistertech-JP/nimbalyst-ja-unofficial.git` であることを確認し、通常pushでmainを進めます。
5. `v0.81.7-ja.1` の新規タグを作成してpushし、同名タグが存在する場合は停止します。本家用のバイナリ配布ワークフローは非公式リポジトリでは実行しません。
6. `RELEASE_NOTES_v0.81.7-ja.1.md` を本文とするPrereleaseを作成します。実行バイナリと更新用YAMLは添付しません。ソースアーカイブを添付する場合は対象ファイル一覧とSHA-256を照合します。
7. 公開main、タグ、Prerelease、日英README、LICENSE、ソースアーカイブを読み戻し、旧タグとReleaseが保持されていることを確認します。

## 将来の追従

公式版の更新は固定コミットまたは公式バージョンごとに別の統合作業として扱います。翻訳、非公式製品の識別子、更新無効化、プロトコル方針、公開文書を個別の変更単位として管理し、固定した公式ベースを毎回記録します。Windowsバイナリの一般公開には、パッケージの静的検証に加えて、許可された環境でのインストール、起動、言語切替と再起動保持、認証、関連付け、設定分離、アンインストールの実動作確認が必要です。
